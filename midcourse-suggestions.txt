FEATURE 1: DUE-DATE USER STORIES
--------------------------------
1. Create with a due date

As a user, I can assign an optional due date when creating a task.

Acceptance criteria:
- A valid YYYY-MM-DD value is accepted and returned unchanged.
- Omitting the field results in null.
- An invalid calendar date receives HTTP 422.

2. Edit or clear a due date

As a user, I can replace or remove a task's due date.

Acceptance criteria:
- PATCH with a valid date replaces the current date.
- PATCH with null clears the date.
- PATCH without due_date preserves the current date.
- Other fields remain unchanged.

3. Recognize overdue tasks

As a user, I can clearly identify overdue incomplete tasks.

Acceptance criteria:
- A task is overdue only when its due date is earlier than today.
- A task due today is not overdue.
- A Done task is never overdue.
- The card uses accessible text as well as visual styling.

4. Filter overdue work

As a user, I can show only overdue tasks.

Acceptance criteria:
- A compact overdue control filters the board.
- All three Kanban columns remain visible.
- Columns with no matches show a clear empty state.


FEATURE 2: TAG USER STORIES
---------------------------
1. Create with tags

As a user, I can enter a simple comma-separated tag list.

Acceptance criteria:
- Tags are trimmed and returned as a string list.
- Blank tags receive HTTP 422.
- Valid tags appear as chips on the task card.

2. Handle duplicates predictably

As a user, I do not get duplicate versions of the same tag.

Acceptance criteria:
- Duplicate comparison is case-insensitive.
- First spelling and order are retained.
- The same behavior applies to POST and PATCH.

3. Edit or clear tags

As a user, I can replace or remove all tags.

Acceptance criteria:
- PATCH with a list replaces the current tags.
- PATCH with [] clears the tags.
- PATCH without tags preserves the current list.
- Unrelated fields remain unchanged.

4. Filter by tag

As a user, I can filter tasks by tag alongside the overdue filter.

Acceptance criteria:
- Tag matching is case-insensitive.
- Tag and overdue filters combine with AND behavior.
- Clearing filters restores all tasks.
- No matches produce clear empty states.


MINI-ADR
--------
Due-date representation:
- Use Python date | None in Pydantic models.
- Serialize as an ISO calendar date: YYYY-MM-DD.
- Use null to clear the field.

Tag representation:
- Use list[str] with an empty-list default.
- Normalize through a shared Pydantic validator.
- Use [] to clear all tags.

Overdue computation:
- Compute rather than store overdue state.
- A task is overdue when due_date exists, due_date < today, and status != Done.
- Computing avoids stale state after a status/date change or a new calendar day.

Filtering API:
- GET /tasks?overdue=true
- GET /tasks?tag=backend
- GET /tasks?overdue=true&tag=backend
- Combined filters use AND behavior.

Rejected complexity:
- Arbitrary date strings because they weaken validation
- Persisted is_overdue flags because they become stale
- Tag IDs, colors, and management screens
- Database and migrations
- Frontend frameworks or complex autocomplete controls
